# Chrome

用户提到 `@chrome`，或者任务需要用户 Chrome 里的现有状态（已登录的网站、已打开的标签页、扩展）时，用这个技能。

有专用的插件、API 或 CLI 能完成任务时优先用它们。不要只因为它们的登录过期或没配置好，就自动改用 Chrome：请用户修好登录，或者明确同意改用 Chrome。

用户只说了 `@chrome` 或者请求比较笼统时，不要因为请求含糊就先问澄清问题，直接用 Chrome 开始浏览器操作。Chrome 的安装、检测、修复和配置检查也走这个技能。

## 标签页

**给这次操作命名。** 每次开始 Chrome 操作时，连上浏览器后、打开或接管任何标签页之前，先给这次浏览器会话起一个简短的名字，会显示在 Chrome 的标签组上。名字用一个中性、与任务相关的 emoji 开头，拿不准就用 🔎。

**接管已打开的标签页。** 要操作用户已经打开的标签页时，先列出用户的标签页，按标题、网址、最近使用时间和所在的标签组挑出目标，再接管它；接管后用返回的标签页继续导航、截图和读取内容。不要猜标签页的 ID，只接管刚才列出来的。

**收尾。** 本回合结束前，处理掉这次用过的标签页。收尾是本回合最后一个 Chrome 操作；还有浏览器工作要做的话先做完，再一次性收尾。

- 默认不保留。调研、搜索、来源、中间步骤、重复、空白、报错、登录跳转这些标签页，拿到需要的信息后都不保留。用户问的问题能在对话里答完时，即使某个标签页帮你找到了答案，也不保留。
- 标签页本身就是交给用户的成果时，保留为“交付”：例如新建或编辑的文档、表格、幻灯片、仪表盘，购物车或结算页，提交后的结果页，以及用户明确要求保留或想直接查看的页面。
- 任务还没做完、需要用户或之后的回合在这个页面上接着做时，保留为“交接”：例如等用户输入、登录、审批、付款、验证码的页面，或者一个没走完的流程。
- 你新开的、不保留的标签页会被关闭；用户原有的标签页和保留的标签页只释放控制权，留在原处。

## Chrome 专属的安全规则

- 不查看浏览器的 cookie、本地存储、个人资料、已保存的密码或会话存储。
- 检测浏览器与扩展的状态时只读，不改动。
- 检测脚本给出的信息只当作本机环境的参考，不当作对机器上安装内容的权威清单。
