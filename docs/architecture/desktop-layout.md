## 1. 名词

```text
┌─────────┬──────────────────── top bar (44, window title bar) ────────────────────────┐
│         ├────────────────────────────────┬─┬─────────────── pane area ───────────────┤
│         │ primary pane                   │ │ ┌─ pane (card) ──────┐ ┌─ pane ───────┐ │
│ sidebar │ = the session the URL points   │s│ │ header: tabs       │ │ header       │ │
│         │   to: transcript, approvals,   │p│ │ active tab content │ │              │ │
│         │   composer                     │l│ │                    │ └──────────────┘ │
│         │ + pinned summary card floating │i│ │                    │ ┌─ pane ───────┐ │
│         │   at the top right             │t│ │                    │ │ header       │ │
│         │                                │ │ └────────────────────┘ └──────────────┘ │
└─────────┴────────────────────────────────┴─┴─────────────────────────────────────────┘
```

- **侧栏**：左边的“项目 → 会话”树（U5 起界面上的“工作区”叫“项目”，协议仍是 workspace），规则不变。
- **内容区**：侧栏右边、顶栏下面的矩形，宽 `C`、高 `Hc`。主窗格与窗格区分它。
- **主窗格**：显示 URL 指的东西（会话、新会话草稿、首页、未找到）。只有一个，不能关，跟着路由换。
- **窗格区**：主窗格右边放辅助窗格的区域，可以收起。
- **窗格**：窗格区里的一张卡片，有窗格头，装一个或多个**标签**；一次显示其中一个。
- **标签**：某个**窗格种类**的一个实例，例如“概览”、文件 `src/a.ts` 的预览。
- **排布**：窗格在窗格区里怎么摆（§4.3 的模板），由窗格的数量、种类与可用空间算出来，不由用户摆。
- **折叠**：空间不够时，把几个窗格并成一个窗格的几个标签显示；窗口变大后自动拆回。
- **浮层**：窗格区停靠不下时，从右边盖在主窗格上。
- **最大化**：一个窗格临时占满整个内容区。

## 2. 窗格模型

### 2.1 种类

| 种类 | ID | 阶段 | 内容属于 | 能否多开 | 最小 宽 × 高 | 形状 | 打开入口 |
|---|---|---|---|---|---|---|---|
| 会话消息流（主） | — | 现在 | URL 里的会话 | 主窗格只有一个 | 440 × 280 | — | 路由 |
| 概览 | `overview` | U18 起退役：并进会话侧栏的“环境”卡片（§12），种类保留以读回旧的本机状态，不再出现在“打开窗格”里 | 当前会话：工作区目录、相关文件 | 否 | 280 × 160 | 矮 | 读回的旧标签 |
| 子智能体 | `subagents` | 现在（R5，§10） | 当前会话的子会话；详情由 URL 决定（§5.2） | 否，列表与详情在同一个标签里切换 | 300 × 200 | 高 | 置顶摘要的“子智能体”节、消息流里的子 agent 标记、“打开窗格”菜单 |
| 变更 / Diff | `changes` | 以后 | 当前会话改过的文件；以工作区 git 状态为准还是以会话为准，由做它的任务定 | 否，单个文件的 Diff 在这个标签里切换 | 360 × 240 | 高 | 置顶摘要的“变更”节、“打开窗格”菜单 |
| 文件预览 | `file` | 以后 | 工作区里的一个文件 | 是，每个文件一个标签；同一个文件只开一次 | 360 × 240 | 高 | 消息流与工具卡片里的文件路径、变更列表 |
| 后台任务 | `tasks` | 现在（U21，§15） | 当前会话的子会话（截图 05 左栏，`design-refs/claude-code-parallel-sessions/` 08–09） | 否 | 300 × 200 | 高 | 窗格区开关（没有窗格时）、会话侧栏的“后台任务”卡片、“打开窗格”菜单 |
| 计划与清单 | `plan` | 以后（R3 有计划事件之后） | 当前会话的计划 | 否 | 280 × 160 | 矮 | 置顶摘要、“打开窗格”菜单 |
| 终端 | `terminal` | 以后 | 工作区（放在打开它的会话里） | 是 | 360 × 160 | 矮（以后可能放到主窗格下面，图 M） | “打开窗格”菜单 |
| 会话（并排） | `session` | 以后 | 另一个会话 | 是，每个会话一个 | 400 × 280 | 高 | 侧栏会话行的“在窗格中打开” |
| 设置 | — | 现在 | 全局 | — | 整窗 | — | 不进窗格模型：整窗页面 `/settings/:tab`（§5.2 第 5 条） |

- **最小尺寸**是整个窗格的尺寸，含 36 px 的窗格头。一个窗格的最小尺寸取它所有标签里最大的那个，切换标签时排布不跳。
- **形状**影响排布（§4.3）：“高”的窗格优先占整列；“矮”的窗格上下叠放时分得少一些。终端以后要不要放到主窗格下面（§4.7 图 M）由做终端的任务定，R12 里它的占位按普通窗格排。
- 阶段为“以后”的种类，R12 只登记种类、最小尺寸与占位内容（“以后的任务实现”），**只在开发模式**的“打开窗格”菜单里出现，用来检查排布；正式构建里看不到。

### 2.2 窗格集属于谁

- **每个会话一套窗格**（新会话草稿用 `draft:<工作区 ID>`），切换会话时窗格区换成那个会话的那一套。这是现在右栏“每会话一组标签”（`right-panel-tabs.ts`）的延续。
- 内容属于工作区的种类（文件、终端）也挂在打开它的那个会话里，不跨会话出现。
- 首页、未找到页没有窗格区，窗格区开关不显示。
- 草稿发出第一条消息变成会话时，草稿的窗格集搬到新会话 ID 下，草稿的清空。

### 2.3 数据结构

```ts
// pane-kinds.ts
type PaneKind = 'overview' | 'subagents' | 'changes' | 'file' | 'tasks' | 'plan' | 'terminal' | 'session';

interface PaneKindSpec {
  minWidth: number;               // 含 36 px 的窗格头
  minHeight: number;
  shape: 'tall' | 'compact';
  multiple: boolean;
  /** 能多开的种类按哪个参数判断“同一个”，例如文件按 path；没有这个参数时每次都新开。 */
  identityParam?: string;
  /** false：以后的种类，只在开发模式里能打开占位。 */
  available: boolean;
}

// pane-state.ts

interface PaneTab { id: string; kind: PaneKind; params?: PaneParams }
interface PaneGroup { id: string; tabs: PaneTab[]; activeTabId: string }

/** 一个会话（或草稿）的窗格状态，持久化（§5）。 */
interface ScopePanes {
  groups: PaneGroup[];            // 排列顺序
  focus: string[];                // 最近聚焦在前，'primary' 是主窗格
  auxVisible: boolean;
  splitHint?: 'right' | 'down';   // 最近一次拆分的方向，两个窗格时优先（§4.3）
  sizes: {
    aux: { 1?: number; 2?: number };   // 窗格区宽度占内容区的比例，按列数分开记
    splits: Record<string, number[]>;  // 拆分节点的比例（和为 1），键是节点在模板里的位置：rows2、side3、side3/1……
  };
}

// arrange.ts：排布的结果是一棵窗格树，叶子是要显示的窗格（可能是并在一起的几个窗格组），内部节点是横向或纵向
// 的拆分，尺寸是像素。
type LayoutNode =
  | { type: 'pane'; pane: DisplayPane }  // DisplayPane：id、groupIds、tabs、activeTabId、segmentStarts、最小尺寸
  | { type: 'split'; key: string; direction: 'row' | 'column'; children: LayoutNode[]; sizes: number[]; mins: number[] };
```

状态里只有窗格组的顺序与比例，没有“谁在左谁在右”的树；树每次由排布函数从状态与窗口尺寸算出来（§4.2）。这样窗口变宽变窄、窗格开开关关时布局总是确定的，纯函数可以穷举测试。

## 3. 操作

### 3.1 打开

`openPane(kind, params, from)` 按顺序：

1. 已经有同一个标签（单开的种类按种类，多开的按 `identity`）：激活它，聚焦它所在的窗格；窗格区收起着就显示出来，它被折叠着就让它所在的显示窗格激活它，另一个窗格最大化着就先还原。
2. 从某个窗格头的“＋”打开：加进那个窗格，成为当前标签。
3. 多开的种类已经有窗格装着同种的标签（例如已经开着别的文件）：加进那个窗格。
4. 否则新建一个窗格放在最后（Claude Code 的做法：每种东西一个窗格，截图 05）。

新打开的窗格获得焦点。窗格区没有窗格时按窗格区开关，打开“后台任务”（U21 起；原来是“概览”，U18 并进了会话侧栏，U18–U20 之间是“子智能体”）。

### 3.2 关闭

- 标签上的“×”关这个标签；窗格里最后一个标签关掉，窗格就没了。窗格头的“×”关整个窗格（截图 05）。
- 最后一个窗格关掉后窗格区随之消失，主窗格占满内容区。
- 现在没有需要“未保存”确认的种类；以后有编辑器类的窗格再加。
- 由 URL 决定的标签（R5 的子 agent 详情）关掉时导航回父会话（§5.2）。

### 3.3 调尺寸

- 主窗格与窗格区之间、窗格区里每两个窗格之间各有一条分隔条，占它们之间 8 px 的间距，鼠标在上面时显示 1 px 的线与左右（或上下）拖动光标，改写自现在的 `sidebar-resizer.tsx`。
- 拖动时两边都不小于各自的最小尺寸；松开时把比例记进当前会话（§5.1）。比例按排布模板分开记，从“上下两个”变成“一列加上下两个”再变回来时，各自的比例还在。
- 键盘：分隔条可以聚焦，方向键每次 16 px；双击恢复默认比例。ARIA 是 `role="separator"`，`aria-valuenow` 用百分比。
- 侧栏的拖动不变（220–400，双击回 260）。

### 3.4 最大化与还原

- 窗格头的“最大化”按钮、双击窗格头的空白处、或快捷键：这个窗格占满整个内容区（主窗格与其他窗格暂时不显示，状态都在）；侧栏与顶栏不变。
- 还原：同一个按钮（变成“还原”）、双击、快捷键，或焦点在最大化的窗格里时按 Esc（Esc 没被窗格里的东西用掉才算）。
- 在“已打开的标签页”里点另一个窗格的标签会先还原。
- 最大化只在本次运行里有效，不保存。主窗格没有最大化按钮：收起窗格区就是它的“最大化”。

### 3.5 拆分与合并

- 窗格头“⋯”菜单里的“拆分到右侧”“拆分到下方”：把当前标签移进一个紧跟在后面的新窗格；只有一个标签时不可用。拆分方向记为 `splitHint`，只在恰好两个窗格时影响排布（§4.3）；更多窗格时由排布规则决定位置。
- “移到 ▸ 〈另一个窗格〉”：把当前标签并进别的窗格。
- 拖动标签到别的窗格或窗格边缘：以后再做，R12 不做。

### 3.6 窗格里的标签

- 窗格头高 36 px：左边是标签条（或标题），右边是“⋯”、“最大化”、“×”（截图 05）。窗格头和内容之间不画分隔线。
- 只有一个标签、而且是单开的种类时，窗格头显示标题（图标 + 名称，例如截图 05 的“Background tasks”）；有两个以上标签、或者是能多开的种类（文件），显示标签条，每个标签有图标、名称和“×”（截图 03、05）。
- 标签条末尾有“＋”：弹出能打开的种类，选中的加进这个窗格（截图 03）。
- 标签放不下时标签条横向滚动；全部标签在“已打开的标签页”里都看得到（§3.7）。
- 被折叠在一起的几个窗格，标签条里按原来的窗格分段，段之间一条竖线；“⋯”菜单里多一项“空间不够，已合并 N 个窗格”的说明（不可点）。

### 3.7 已打开的标签页

- 顶栏右侧的计数按钮（截图 07）：数字是当前会话打开的标签数，没有标签时不显示。窗格区显示与收起时都在。
- 点开是一个列表：标题“已打开的标签页”，每行图标 + 名称（多个窗格时按窗格分组，组之间一条分隔线），悬停时右边出现“×”；点一行就按 §3.1 第 1 条显示它。
- 列表底部一行“打开窗格 ▸”，子菜单列出能打开的种类（开发模式下还有以后的种类的占位）。
- 键盘可以完全操作：上下键移动、回车打开、Delete 关闭，Esc 收起。

### 3.8 置顶摘要卡片（U18 起由会话侧栏取代）

R12 的置顶摘要卡片浮在主窗格右上角，各功能用 `registerSummarySection` 登记一节；2026-10-15 维护者先去掉了它的开关按钮（截图 08 的图钉，多数时候没有内容、按钮不可用），同日确认 U18 的会话侧栏（§12）取代它：卡片不再显示，登记方式扩成侧栏卡片的 `registerRailCard`，“子智能体”一节改成侧栏的“后台任务”卡片。

### 3.9 窗格区的显示与收起

- 顶栏最右边的“窗格区”按钮（现在的右栏开关的位置）：显示或收起窗格区；收起不关窗格，计数按钮还在。没有窗格时按它打开“后台任务”（§3.1）。
- 浮层模式（§4.6）下按它打开或关闭浮层。

### 3.10 键盘快捷键

macOS 用 ⌘，Windows 与 Linux 用 Ctrl。快捷键写在对应按钮的提示里。

| 操作 | macOS | Windows / Linux | 说明 |
|---|---|---|---|
| 显示 / 收起侧栏 | ⌘B | Ctrl+B | 已有 |
| 后退 / 前进 | ⌘[ / ⌘] | Ctrl+[ / Ctrl+] | U5，同窗口左上角的两个箭头 |
| 显示 / 收起窗格区 | ⌘⌥B | Ctrl+Alt+B | 新 |
| 已打开的标签页 | ⌘⇧A | Ctrl+Shift+A | 新 |
| 最大化 / 还原当前窗格 | ⌘⇧M | Ctrl+Shift+M | 新；焦点在最大化的窗格里时 Esc 也能还原 |
| 拆分当前标签到右侧 | ⌘\ | Ctrl+\ | 新 |
| 当前窗格的下一个 / 上一个标签 | ⌃Tab / ⌃⇧Tab | Ctrl+Tab / Ctrl+Shift+Tab | 新 |
| 焦点移到下一个 / 上一个窗格（含主窗格） | ⌘⌥→ / ⌘⌥← | Ctrl+Alt+→ / ← | 新，按从左到右、从上到下的顺序 |
| 关闭当前标签 | 无 | 无 | 不接管 ⌘W（维护者 2026-10-14），它仍是 Electron 默认菜单的“关闭窗口”；键盘在标签上按 Delete 关闭 |

焦点在输入框里时上面这些照样生效（都不是文本编辑常用的组合）；输入法合成期间不响应。

### 3.11 焦点与无障碍

- 点窗格的任何地方都会把它记为最近聚焦（`focus` 的第一个）；聚焦的窗格头文字用正文色，其他窗格头用次要色。键盘焦点只用 `focus-visible` 的焦点环。
- 窗格是 `role="region"`，名字是当前标签的名称；标签条是 `tablist` / `tab` / `tabpanel`。
- 浮层与弹出框关闭后焦点回到打开它的按钮（现在的做法）。

## 4. 动态布局规则

### 4.1 尺寸

| 名称 | 值 | 说明 |
|---|---|---|
| 窗口最小 | 960 × 600 | 不变（`main/index.ts`） |
| 顶栏高 | 44 | 不变 |
| 侧栏宽 | 220–400，默认 260 | 不变 |
| 侧栏能停靠 | 视口宽 − 560 ≥ 220 | 不变：主窗格的舒适宽度仍按 560 算，视口 < 780（放大界面后）侧栏改浮层 |
| 主窗格最小 | 440 × 280 | 窗格区停靠时主窗格至少这么宽；比现在的 560 窄，换来 1024 左右的窗口也能并排 |
| 间距 | 8 | 主窗格与窗格区之间、窗格之间、窗格区与窗口右边和上下边之间 |
| 窗格头高 | 36 | |
| 窗格区默认宽 | 一列时内容区宽的 40%，两列时 58% | 用户拖过以后按列数分开记 |
| 浮层宽 | min(C − 48, max(420, 排布最小宽 + 16)) | |
| 同时显示的窗格 | 最多 4 个 | 多出来的折叠成标签 |
| 会话侧栏 | 宽 288（加右边 8 的间距），不可拖 | U18，§12；停靠后主窗格仍要 ≥ 440，否则改浮层 |

记号：`W × H` 是视口（CSS px，界面缩放时会变），`C` 是内容区宽 = `W` − 停靠的侧栏宽，`Hc` 是内容区高 = `H` − 44（U25 起连接通知是右下角的浮层，不占高度），窗格区的可用高 `Hr` = `Hc` − 16。

### 4.2 算法

`arrangeWorkbench(input) → plan` 是纯函数，输入视口、侧栏偏好、当前会话的 `ScopePanes`、最大化的窗格、种类表，输出侧栏的摆法、窗格区的模式（无 / 停靠 / 浮层 / 最大化）与一棵窗格树。

1. **侧栏**：照现在的 `planLayout`（停靠、收起、浮层），得到 `C`。
2. **没有窗格、或窗格区收起**：主窗格占满内容区（单窗格）。
3. **有窗格最大化**：它占满内容区，结束。
4. **能停靠吗**：窗格区最多能有 `Amax = C − 440 − 16` 宽（主窗格最小 440，加两道间距）。按 §4.3 为当前的窗格数挑第一个放得下（宽 ≤ `Amax`、高 ≤ `Hr`）的模板；挑不到就把窗格数减一（折叠，§4.4）再挑，直到一个窗格。
5. **一个窗格也停靠不下**（`Amax` 小于它的最小宽）：窗格区改浮层，浮层宽按 §4.1，里面只排一列，按第 4 步同样的办法挑模板。
6. **窗格区宽**：`A = clamp(比例[列数] × C, 模板最小宽, Amax)`，比例取当前会话记住的，没有就取工作区最近用的，再没有就用默认的 40% / 58%。主窗格宽 `C − A − 16`。
7. **模板里各窗格的尺寸**：每个拆分节点按记住的比例（没有就用默认比例）分配，低于最小尺寸的先补到最小，差额从其他还有余量的子节点按比例扣。

### 4.3 排布模板

`n` 是要显示的窗格数（已经扣掉折叠的）。每行的候选按顺序试，第一个放得下的胜出。

| n | 模板 | 结构 | 最小宽 | 最小高 | 默认比例 |
|---|---|---|---|---|---|
| 1 | `one` | 一个窗格 | w₁ | h₁ | — |
| 2 | `rows2` 上下 | 列：G1 / G2 | max(w₁, w₂) | h₁ + h₂ + 8 | “高”+“矮”时 60 / 40，否则 50 / 50 |
| 2 | `cols2` 左右 | 行：G1 \| G2 | w₁ + w₂ + 8 | max(h₁, h₂) | 50 / 50 |
| 3 | `side3` 一列高 + 一列上下 | 行：T \| (列：X / Y) | w_T + max(w_X, w_Y) + 8 | max(h_T, h_X + h_Y + 8) | 50 / 50；右列同 `rows2` |
| 3 | `rows3` 三个上下 | 列：G1 / G2 / G3 | max(w) | Σh + 16 | 按“高”3、“矮”2 的权重 |
| 4 | `grid4` 网格 | 行：(列：G1 / G2) \| (列：G3 / G4) | max(w₁, w₂) + max(w₃, w₄) + 8 | max(h₁ + h₂, h₃ + h₄) + 8 | 50 / 50，各列 50 / 50 |

两个窗格时的先后：`splitHint` 是 `right` 就先试 `cols2`，是 `down` 先试 `rows2`；没有提示时两个都是“高”的窗格（例如两个文件）先试 `cols2`，否则先试 `rows2`。三个窗格先试 `side3`（截图 05 的样子），其中 T 取排列顺序里第一个“高”的窗格（都不是就取第一个），X、Y 是其余两个，保持排列顺序。四个窗格只有 `grid4`，放不下就折叠成三个。五个以上先折叠成四个。

窗格在模板里的位置只由排列顺序与“第一个高窗格”决定，新开的窗格总是排在最后；所以打开第三个窗格时，原来上下两个里的第一个会移到左边占整列（截图 05 就是这样）。

### 4.4 折叠到标签

要显示的窗格数 `k` 小于实际窗格数 `n` 时：排列顺序里前 `k − 1` 个窗格原样显示，其余的并成最后一个显示窗格；标签按原来的排列顺序拼起来，当前标签取它们之中最近聚焦的那个窗格的当前标签；它的最小尺寸取被并窗格的最大值。所以刚打开的窗格放不下时，会作为当前标签出现在最后一个窗格里。

谁被并只看排列顺序、不看焦点：按焦点决定的话，点进一个被并的窗格就会把别的窗格挤进去，布局跟着跳（设计稿 v0.1 是按焦点的，实现时改了）。

折叠只影响显示，状态里的窗格不变；窗口变大或关掉别的窗格后自动拆回原样。

### 4.6 窄窗口与矮窗口

- **窄**：先按 §4.2 第 4 步折叠，一个窗格也停靠不下才改浮层。不自动收起侧栏腾地方（侧栏是用户自己管的），浮层的提示里写“收起侧栏可以并排显示”。
- **更窄**（视口 < 780）：侧栏也改浮层（不变），窗格区按同样的规则停靠或浮层。
- **矮**（`Hr` 放不下上下叠放）：上下的模板放不下就试左右的，都不行就折叠；高度不会让窗格区改浮层，因为一个窗格的最小高 ≤ 240，总能放下。
- **会话侧栏**：先算侧栏停靠时窗格区与主窗格还排不排得下（主窗格 ≥ 440、窗格区不用改浮层），排不下侧栏就改浮层，窗格区再按上面的规则排（§12）。
- 浮层沿用现在的 `Sheet`：整窗高，自带关闭按钮，关掉后焦点回到窗格区按钮。

## 5. 状态的保存

### 5.1 记在哪里

| 状态 | 范围 | 存在哪 | 什么时候清 |
|---|---|---|---|
| 侧栏宽度、手动收起、收起的工作区；会话侧栏开着与否、展开了哪些卡片（U18） | 全局 | localStorage `wevir.layout.v2`（由 v1 迁来） | — |
| 窗格（组、标签、当前标签）、焦点顺序、窗格区显示与否、`splitHint` | 每个会话（草稿 `draft:<工作区 ID>`） | localStorage `wevir.panes.v1` | 会话从列表里消失时；最多 200 个会话，按最近使用淘汰 |
| 窗格区宽度比例（按列数）、各模板的分隔比例 | 每个会话；新会话从所在工作区最近一次调过的比例开始 | 同上（会话一份、工作区一份） | 工作区从列表里消失时 |
| 最大化、浮层开着、拖动中的尺寸 | 本次运行 | 内存 | 重启 |

- 新会话没有辅助窗格，只继承尺寸，不继承窗格。
- 只记 ID、种类与参数（例如文件的相对路径），不放会话内容或文件内容（与 `last-location.ts` 同一口径）。
- 读的时候逐项校验：不认识的种类（例如新版本存的、再用旧版本打开）、参数不合格式的标签丢掉；丢完为空的窗格丢掉；比例不在 (0, 1) 的丢掉回默认。
- 清理只在列表读成功（`status: 'ready'`）时做，Host 断开时不清。

### 5.2 URL 与窗格状态

1. **URL 仍是“看哪个工作区、哪个会话”的唯一事实。** 主窗格永远显示 URL 指的东西；窗格区的组成不进 URL，它是这个会话的界面状态，从本机恢复。刷新页面得到的是同一个 URL 加同一份本机状态，结果相同。
2. **可寻址的窗格内容才进 URL，而且只在主会话的路径下面加一段。** 目前只有 R5 的子 agent 详情：`/workspace/:wid/session/:sid/agent/:childId`。路由带这一段时，布局保证“子智能体”标签打开并显示这个子会话（没有就按 §3.1 打开，记进窗格状态）；用户在标签里点返回或关掉它，就导航回 `/workspace/:wid/session/:sid`。一个 URL 最多带一段这样的东西。以后文件预览要能分享或“后退”时，同样加段。
3. **打开、关闭、调尺寸、最大化、拆分都不产生历史记录。** “后退”只撤回路由的变化：换会话、进出子 agent 详情、进出设置。
4. **窗格里的东西找不到时只在那个窗格里显示“未找到”**（子会话、文件），不回落到别的内容；主窗格的“未找到”规则不变。
5. **设置是整窗页面 `/settings/:tab`**，不进窗格模型，返回时回到打开设置前的位置（不变）。上次打开的位置（`last-location.ts`）照旧只记工作区与会话；U4 起（维护者 2026-10-14 定）只记工作区，新开窗口停在首页，记下的工作区是首页标题里工作区下拉的默认值。

### 5.3 存储格式

```ts
// localStorage 'wevir.panes.v1'
interface StoredPanes {
  version: 1;
  scopes: Record<string, ScopePanes & { usedAt: number }>; // 键是会话 ID 或 draft:<工作区 ID>
  workspaces: Record<string, ScopePanes['sizes']>;         // 每个工作区最近一次调过的尺寸，新会话从它开始
}
```

写入在操作结束时做（松开分隔条、开关窗格），拖动中只改内存里的草稿；操作没有改变状态（例如点一下已经是最近聚焦的窗格）时不写。版本不对或读不出时从空的开始。

## 10. R5：“子智能体”窗格

照 Codex 桌面端的截图（`design-refs/` 01–04、06–08）与 ADR-0005 决策 6.1、补记 10。代码在 `layout/panes/subagents-pane.tsx`（窗格与置顶摘要的一节）与 `session/` 下的 `subagent-*.tsx`、`subagent-model.ts`、`avatar.ts`。

- **种类**：`subagents` 正式可用（`available: true`），单开，最小 300 × 200，“高”。打开入口：置顶摘要的“子智能体”一节、消息流里子会话的“开始工作 / 已完成”两行、父会话审批卡片上的“查看子智能体”、“打开窗格”菜单。
- **内容随 URL**（§5.2）：`/workspace/:wid/session/:sid` 时是当前会话的子会话列表——“已开启 · N”（运行中的，最近派出的在前；没有时“没有已开启的子智能体”）与“完成 · N”（完成、运行失败、已关闭、已取消，最近结束的在前；为 0 时不显示这一组），每项头像、标题、相对时间，运行中在等审批的标“等待审批”，运行失败与已取消标出状态。`…/agent/:childId` 时是这个子会话的视图：窗格头下面一行返回箭头、头像、标题、右边“模型 · 推理强度”，再下面“用时”（运行中每秒跳）与它的消息流（复用 `TranscriptView`），底部是它的审批与“子智能体由父 agent 驱动，这里只能查看。”，没有输入框。
- **路由**：`agent/:childId` 是会话路由的子路由（`routes/router.tsx`），进出详情时主窗格的会话视图不重建（滚动位置、输入框草稿都在）。进入详情时工作台布局按 §3.1 打开“子智能体”标签（窗格区收起、在浮层或被最大化的窗格盖住时也显示出来）；还在详情的地址时这个标签被关掉，就导航回父会话（`workbench-layout.tsx` 的 `useSubagentRoute`）。窗格区的浮层只在换会话时收起，进出详情不收（详情就画在浮层里）。子会话不属于这个会话、或回放追平后还找不到时，窗格里显示“找不到这个子智能体”。
- **置顶摘要**（U18 起改成会话侧栏的“后台任务”卡片，§12）：“子智能体”一节（`order` 20），标题“子智能体”，下面一行最近派出的至多 5 个头像与“N 进行中 · M 完成”，点它打开窗格。会话没有子会话时这一节为 `null`，按钮照旧不可用。
- **头像**：`avatarFor(sessionId)` 用 32 位 FNV-1a 从会话 ID 选出 `--avatar-1 … 7`（靛蓝、青、绿、琥珀、紫、湖蓝、粉，主色第 9 阶、辅色第 7 阶）与八种几何形状之一，16 px 的 SVG（`subagent-avatar.tsx`）。同一个子会话在消息流、列表、详情、审批与摘要里是同一个样子。

## 11. U5：窗口框架与侧栏（照 Codex 桌面端）

维护者 2026-10-14 定，参考 Codex 桌面端的截图。

- **窗口按钮**：红绿灯后面是后退、前进与侧栏开关（`layout/window-controls.tsx`）。后退、前进走 hash 路由的历史：React Router 在 `history.state.idx` 里给每条记录编号，`lib/history-nav.ts` 在路由根（`routes/router.tsx` 的 `AppRoot`）记下当前序号与后退前到过的最大序号，据此判断能不能后退、前进；快捷键 ⌘[ / ⌘]（§3.10）。工作台里这组按钮放在根节点的最后、绝对定位在左上角（拖动区按文档顺序计算，放在后面才盖得住侧栏与顶栏的拖动区）；侧栏以浮层打开时，浮层的头里另有一组。设置页只有后退、前进，历史里退无可退时后退回首页。
